# PnP Bridge 1.19.0

## Fixed

- **`NCSP11001: User intent validation failed` on provisioning — a switch has to
  be provisioned to a building, not a floor.** Cisco's "Assign network devices
  to a site" reference states it plainly: *"Access points, Sensors are assigned
  to floor. Remaining network devices are assigned to building."*

  The site mapping resolved to `Global/00_EMEA/Stockdorf - STO/Building 3/U3` —
  `U3` is a floor — and Catalyst Center rejected the intent. The HTTP verb
  (POST vs PUT, tried in 1.16.0) was never the problem.

  Before provisioning, PnP Bridge now looks the mapped site up and, if it is a
  floor, substitutes its building parent. Buildings and areas are used as-is.
  Your site mapping does not need to change — mapping to a floor stays valid,
  and the wizard still shows the floor.

- **Provisioning failures now report the underlying reason.** The task tree is
  drilled even when `failureReason` is already set, because the top-level reason
  is the generic NCSP11001 and the validation that actually objected only names
  itself in a child task.

## Upgrade notes

- No schema change. `git pull && make image`, recreate the container.
- Turn Settings → Provisioning → "Provision to site after claim" back **on** to
  try it: it has been off by default since 1.17.0.
