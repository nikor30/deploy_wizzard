# PnP Bridge 1.10.0

A Day-N deploy fix plus more fields matched from NetBox.

## Fixed

- **Day-N deploy no longer fails with HTTP 404.** Some Catalyst Center builds do
  not expose `template/deploy/v2`. The deploy now falls back to the older
  `template/deploy` path (same request body) when — and only when — v2 answers
  404. Any other error (a bad template id, a rejected payload) still surfaces as
  itself, so a real problem is never hidden behind the fallback.

## New — more Day-N values matched from NetBox

- **Uplink description** — always `UPL:<switch>`, where the switch is the
  far-end device of the device's cabling in NetBox (e.g. `UPL:ssto199cis`).
  Fills `UPLINK_DESCRIPTION` and `UPLINK CONFIGURATION INFORMATION`.
- **Port-channel id** — `1` for switches whose NetBox role is **access** (their
  single uplink port-channel). Other roles stay a manual field, since that is a
  design decision. Fills `PO_ID`, `PORTCHANNEL_ID`.
- **Access and critical VLAN** — taken from the VLANs of the device's site by
  **name**: the VLAN whose name contains "access" fills `ACCESS_VLAN`, the one
  containing "critical" fills `CRITICAL_VLAN_ID`. Matching is
  case-insensitive. If two VLANs at a site match the same keyword the result is
  ambiguous, so the field stays manual rather than guessing.

As always, an explicit mapping under Settings → Day-N Variables overrides any of
these.

## Upgrade notes

- No schema change. `git pull && make image`, recreate the container.
- Jobs sitting on step 4 need "Resolve variables" once more to pick the new
  values up.
