# PnP Bridge 1.10.1

Composite Day-N templates now deploy correctly.

## Fixed

- **Composite templates are deployed member by member.** Catalyst Center cannot
  render a composite template on its own — deploying the container pushed its
  member list to the switch as CLI text, which the device rejected
  (`% Invalid input detected`), and the deploy came back without a task id
  ("deploy/v2 did not return a taskId").

  The deploy now expands a composite into its member templates and deploys each
  one in declaration order, waiting for each task before starting the next. The
  NetBox device is only set `active` once every member has succeeded. A plain
  (non-composite) template is unaffected.

  Each member is sent only the parameters it declares. A plain template still
  receives every resolved parameter, exactly as before.

- **Clearer failure when a deploy returns no task id.** The message now names
  the template that was deployed and points at what to check, instead of just
  "deploy/v2 did not return a taskId". Responses that report the task as
  `deploymentId`/`deploymentJobId` are now understood too.

## Upgrade notes

- No schema change. `git pull && make image`, recreate the container.
