# PnP Bridge 1.13.1

Three fixes from the first live run of 1.13.0.

## Fixed

- **A failed provision no longer blocks the whole wizard.** 1.13.0 marked the
  device `failed`, which left you at "Continue to Day-N (0 devices)" with no way
  forward. The claim itself succeeded, so the device now stays `success` and
  Day-N remains available — carrying a `Warning:` that the site's network
  settings were not applied. Loud, but not a dead end.

- **Webhook deliveries answered HTTP 401.** The receiver authenticates the
  *caller* with a token; PnP Bridge only sent an HMAC signature. A signature
  proves the payload came from us — it does not authenticate us, so the receiver
  answered 401 no matter how well the body was signed.

  Settings → ISE Webhook now has an optional **auth token** (stored encrypted,
  masked on read) and **auth header name** (default `Authorization`). The value
  is sent verbatim, so enter any prefix yourself, e.g. `Bearer abc123`.

- **CCC tag creation failed with NCGR10060** ("The specified group name is
  invalid"). Catalyst Center rejects group names containing anything outside
  letters, digits, space, dash, underscore and dot; NetBox role names are free
  text. Role names are now normalised before the tag is created.

## Known issue

The provision call itself is still rejected with `NCSP11001: User intent
validation failed while processing the 'provision' request`. The endpoint exists
and accepts the request shape, but the controller rejects the intent — a GUI
capture of a manual provision is needed to see what it expects. Until then,
either provision by hand in Catalyst Center or turn off Settings → Provisioning
→ "Provision to site after claim".

## Upgrade notes

- **Schema change**: migration `0011` adds `service_settings.auth_header` and
  `auth_token_encrypted`. Runs at startup; no manual step.
- `git pull && make image`, recreate the container.
