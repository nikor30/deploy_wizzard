# PnP Bridge 1.10.2

Day-N deployments are now tracked correctly, plus VLAN preselection.

## Fixed

- **Day-N no longer half-provisions.** Catalyst Center answers a template deploy
  with a *sentence* rather than an id — `Deployment of Template: <uuid>.
  ApplicableTargets: [10.0.0.1]Template Deploymemnt Id: <uuid>` (CCC's own typo
  included). 1.10.1 passed that whole string to the task endpoint, which failed
  with `HTTP 400 … is not a valid UUID`. Because the members of a composite are
  deployed one after another, that error stopped the run after the first member:
  the login banner was applied, but the port/VLAN template never ran.

  The real deployment id is now extracted from the sentence and tracked through
  the deployment-status endpoint, so every member of a composite runs.

- **Failures report the switch's own error.** A failed deployment now surfaces
  the device-level message from Catalyst Center (e.g.
  `Invalid input detected at Vlan900`) instead of a generic failure.

## New

- **Management VLAN is preselected** in the match step from the site's VLAN
  names — a VLAN named `MGMT` (or `Management`) is selected for you to confirm.
  If two VLANs at the site match, none is selected: choosing the wrong
  management VLAN would strand the device.
- **Access / critical VLAN when several candidates match.** A single matching
  VLAN name still fills the field read-only. When several match (e.g.
  `Access-Data` and `Access-Voice`), the lowest VID is now offered as an
  **editable, prefilled** field rather than being left empty — you confirm or
  change it, the same way Day-0 treats its gateway guess.

## Upgrade notes

- No schema change. `git pull && make image`, recreate the container.
- Re-run "Resolve variables" on any job sitting on step 4.
