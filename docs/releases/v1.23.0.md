# PnP Bridge 1.23.0

## The provisioning blocker, found

`business/sda/provision-device` answered:

> **HTTP 403 — Role does not have valid permissions to access the API.**

The endpoint is correct. The **Catalyst Center account PnP Bridge authenticates
as does not have permission to provision.** The GUI succeeds because the
operator's own account has the role.

**Fix it in Catalyst Center:** System → Users & Roles → the account configured in
Settings → Catalyst Center. Provisioning needs write access to *Network
Provision*; a read-only or observer role can claim devices and deploy templates
but not provision.

The error now carries that guidance instead of leaving a bare 403.

## Fixed

- **Log retention could delete the entire log.** With `retention_days` below 1
  the cutoff became "now" and every entry matched. It is now refused with an
  error naming `PNPB_LOG_RETENTION_DAYS`.
- **A failing DB log sink was silent.** Write failures were swallowed, so the
  Logs page stopped updating while the application looked healthy. The first
  failure now prints a structured ERROR to stderr (visible in `podman logs`).

## Upgrade notes

- No schema change. `git pull && make image`, recreate the container.
- If your Logs page is empty, check the container's stderr for
  "DB log sink write failed" after upgrading.
