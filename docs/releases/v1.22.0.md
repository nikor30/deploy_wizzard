# PnP Bridge 1.22.0

## Changed

- **Provisioning now uses the classic "Provision Wired Device" call**, the one
  behind the GUI's Provision action:

  ```
  POST /dna/intent/api/v1/business/sda/provision-device
  {"deviceManagementIpAddress": "...", "siteNameHierarchy": "Global/.../U3"}
  ```

  It takes a management IP and a site *path string* rather than UUIDs, and `PUT`
  re-provisions an already-provisioned device. The `business/sda` path segment
  is historical — this endpoint predates the fabric-specific
  `sda/provisionDevices` and is what wired provisioning has always used.

  `sda/provisionDevices` runs a fabric step that rejects a non-fabric switch
  with `NCHS20057`, which is what has been failing.

- **Settings → Provisioning** now offers three methods:
  - **Provision wired device** (default) — start here for a normal switch.
  - **Assign to site** — attaches the device only; Device Controllability then
    pushes the site's settings.
  - **SDA provision** — the fabric path, for fabric devices only.

## Note

Device Controllability is at **System → Settings → Device Settings → Device
Controllability** in 2.3.7, not under Design → Network Settings.

## Upgrade notes

- No schema change. `git pull && make image`, recreate the container.
- Turn Settings → Provisioning → "Provision to site after claim" **on** and
  leave the method on "Provision wired device".
