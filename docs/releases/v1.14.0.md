# PnP Bridge 1.14.0

## Added

- **HTTP trace** (Settings → Debug → "HTTP trace"). Logs every request and
  response to Catalyst Center and NetBox — including the bodies — to the Logs
  page, so a failing call can be captured and shared for diagnosis.

  Tokens and passwords are redacted before anything is written; a regression
  test asserts the auth token never appears in a traced call. The setting
  applies immediately (no restart) and is restored at startup, so a capture in
  progress survives a container restart.

  It is verbose by design: turn it on, reproduce the problem, turn it off.

- **Access ports are derived from NetBox** rather than guessed from the port
  name. `device.access_ports` is the list of physical, non-management,
  non-uplink interfaces — where "uplink" means NetBox shows the port as cabled
  or connected to another device. Virtual, LAG and bridge interfaces are
  excluded.

  Available as `ACCESSPORTS`, `ACCESSPORTLIST` or `CLIENTPORTS` in a Day-N
  template, plus `ACCESSPORTCOUNT`. The previous `x/0/y` name pattern caught an
  uplink that happened to sit on a front-panel port, and missed a front-panel
  port on a module.

  To use it, replace the `#foreach($interface in $__interface)` loop's filter
  with the resolved list, e.g. iterate `$ACCESSPORTS.split(",")`.

## Upgrade notes

- No schema change. `git pull && make image`, recreate the container.
