# PnP Bridge 1.8.0

Composite template support, plus per-step template filters.

## Fixed

- **Composite templates now resolve their variables.** Selecting a Catalyst
  Center *composite* template produced an empty variable list, so every variable
  it needed silently went unfilled. A composite carries no `templateParams` of
  its own — they live in the member templates under `containingTemplates`. The
  tool now follows those members and unions their variables (a variable shared
  by two members is asked for once). This applies everywhere templates are
  introspected: Day-0 prepare, Day-N prepare, and the Day-N mapping
  suggest/preview.

## New

- **Template filters (Settings → Credentials → "Template filters").** Two
  comma-separated word lists — one for Day-0, one for Day-N — so each wizard
  step only offers the templates meant for it. Matching is a case-insensitive
  substring on the template name, and any word matching is enough (e.g.
  `onboarding, webasto`). Leave a filter empty to keep offering every template.

## Upgrade notes

- No schema change (the filters live in the existing key/value settings table).
  `git pull && make image`, recreate the container.
- Composite templates need no configuration — they are detected automatically.
