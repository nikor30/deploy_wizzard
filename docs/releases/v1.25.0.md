# PnP Bridge 1.25.0

## Changed

- **Templates that reconfigure interfaces are now deployed last.**

  A freshly onboarded switch is still reached over the port PnP used — its
  uplinks are typically not cabled yet. So a port or uplink template
  reconfigures the very interface Catalyst Center is pushing across: the SSH
  session drops, and every template after it fails with *"Connection to device …
  timed out using protocol ssh2"*.

  Composite members are now ordered **safe first, interface-touching last**, so
  the banner, VLANs and the rest are already on the device before anything can
  cut the path. Relative order is preserved within each group.

  A member is treated as disruptive when its name contains `port`, `uplink`,
  `interface`, `trunk`, `channel`, `dot1x` or `ise`.

- **Failures name the template, not its UUID.** `3ca2fdf0-87b2-…: deployment
  failed` is now `IT-DayN-Uplink_Conf: deployment failed`.

## Note

This makes the ordering safe; it does not make the port push itself safe. If the
port template still configures the interface the device is reachable on, that
push will still drop the session — but everything else will already have
applied, and only the port template will be reported as failed.

## Upgrade notes

- No schema change. `git pull && make image`, recreate the container.
