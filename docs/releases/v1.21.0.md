# PnP Bridge 1.21.0

## Fixed

- **Non-fabric switches are now assigned to their site instead of being pushed
  through SDA fabric provisioning.**

  `sda/provisionDevices` runs two child operations: *Assigning Devices to Sites*
  and then *Provisioning assigned Devices*. The task tree from a live run shows
  the first succeeding and the second failing with `NCHS20057` — because the
  second is the **fabric** step, and a plain access switch has no business in it.

  For a non-fabric device the assignment *is* the operation. Per Cisco's "Assign
  network devices to a site" reference: *"If device controllability is enabled,
  it will be triggered once the device is assigned to the site successfully."*
  **Device Controllability** is the feature that pushes the site's network
  settings — SNMP, syslog, NTP, AAA — to the device.

  PnP Bridge now calls
  `POST /dna/intent/api/v1/networkDevices/assignToSite/apply`.

## Added

- **Settings → Provisioning** offers two methods:
  - **Assign to site** (default) — the non-SDA path described above.
  - **SDA provision** — the previous behaviour, for fabric devices only.

## Before you run it

Check **Design → Network Settings → Device Controllability** is enabled. Without
it, assignment attaches the device to the site but pushes no configuration, and
AAA/RADIUS/TACACS will still be missing.

## Upgrade notes

- No schema change. `git pull && make image`, recreate the container.
- Turn Settings → Provisioning → "Provision to site after claim" **on** (it has
  been off by default since 1.17.0) and leave the method on "Assign to site".
