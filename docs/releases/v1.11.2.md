# PnP Bridge 1.11.2

Third and — with Cisco's documentation behind it — final correction to the
Day-N interactive-prompt guidance.

## Fixed

- **The AAA legacy→C3PL prompt is answered on the control class, not by a
  separate command.** Both previously recommended commands were wrong:
  `authentication display new-style` is privileged-EXEC only, and
  `authentication convert-to new-style` is rejected in EXEC mode too. Cisco's
  IOS-XE 17.14 *Configuring Identity Control Policies* guide states the
  confirmation prompt appears "after you enter the first explicit
  Identity-Based Networking Services command, for example when configuring a
  control class or control policy". So the prompt is raised by
  `class-map type control subscriber` — answer it there:

  ```
  #INTERACTIVE
  class-map type control subscriber match-all AAA_SVR_DOWN_AUTHD_HOST<IQ>continue<R>yes
  #ENDS_INTERACTIVE
  !
  class-map type control subscriber match-all AAA_SVR_DOWN_AUTHD_HOST
  match result-type aaa-timeout
  match authorization-status authorized
  ```

  The class-map is re-declared so the `match` lines land in class-map config
  mode regardless of where the interactive block leaves the session.

## Upgrade notes
