# PnP Bridge 1.19.1

## Reverted

- **1.19.0 substituted a floor's building parent when provisioning. That was
  wrong.** A switch can be provisioned to a floor in Catalyst Center. The
  documentation line it was based on — *"Access points, Sensors are assigned to
  floor. Remaining network devices are assigned to building."* — describes the
  assign-to-site default, not a provisioning constraint.

  Silently replacing the mapped floor with its building changed the operator's
  intent for no benefit. The site is used exactly as mapped again.

## Fixed

- **Batch provisioning failures now show the real reason.** Catalyst Center
  answered *"Batch Operation failed. Not all child operations succeeded. Submit
  a GET task tree request using the parent taskId to get complete statuses."*
  PnP Bridge did fetch the tree, but read only `failureReason` — which a batch
  child commonly leaves empty while describing itself in `progress`, or carrying
  a code in `errorCode` with the text in `data`. All four are now read, and the
  drill also triggers whenever CCC's own message points at the task tree.

## Note on the webhook

Deliveries now report `{"detail":"invalid token"}` from the receiver. That means
the auth token *is* being sent and the receiver is rejecting its value — correct
it under Settings → ISE Webhook → Auth token, and use "Send test delivery" to
check it without running a claim.
