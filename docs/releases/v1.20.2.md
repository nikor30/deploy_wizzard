# PnP Bridge 1.20.2

## Fixed

- **The `NCHS20057` hint asserted a cause that has been disproven.** 1.20.0
  blamed AAA; 1.20.1 blamed SNMP and syslog. The template's **Provision
  Conflicts** tab in Catalyst Center reports *"No conflicting commands are
  found"*, so it is not a brownfield configuration conflict at all.

  The hint no longer names a cause. It states what the task tree actually shows
  — the device *was* assigned to its site successfully, and only the
  configuration push was rejected, fast enough that nothing reached the switch —
  and lists what to check: the device's state in Inventory after PnP, whether a
  Network Profile for switching is attached to the site, and whether the site's
  network settings are complete.

## Where this stands

Ruled out so far, with evidence:

| Ruled out | Evidence |
|---|---|
| The site / floor mapping | the `Assigning Devices to Sites` child succeeds |
| A brownfield config conflict | Provision Conflicts: no conflicting commands |
| Anything reaching the switch | the failing child lasts ~6 seconds |

Still open: whether the device is fully collected in Inventory when provisioning
runs, and whether `sda/provisionDevices` is the call this controller expects for
a non-fabric switch. Provisioning the same device by hand in the GUI
distinguishes the two in one action.
