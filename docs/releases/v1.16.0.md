# PnP Bridge 1.16.0

## Fixed

- **Provisioning failed with `NCSP11001: User intent validation failed`.** The
  HTTP trace settled it: the POST is *accepted* — HTTP 202 with a taskId — and
  validation fails later, inside the task. The URL, the body shape and the IDs
  were all correct. The verb was wrong.

  `POST /dna/intent/api/v1/sda/provisionDevices` **creates** a provisioning;
  `PUT` **updates** one. PnP site-claim already registers a provisioning record,
  so POST is rejected for a device that has one. PnP Bridge now looks the device
  up first and re-provisions with PUT when a record exists, carrying that
  record's `id`. A device with no record is still provisioned with POST.

- **Webhook delivery errors were unactionable.** `HTTP 401` alone cannot
  distinguish a missing token from a wrong one or from a rejected payload
  schema. Up to 500 characters of the receiver's response body are now kept in
  the delivery error and shown on the Logs page.

## Added

- **Settings → ISE Webhook → "Send test delivery"** posts a probe event through
  the same sender a real notification uses, so the receiver answers exactly as
  it would for a Day-0 delivery. Auth can be fixed here without running a claim.
  A 401 response adds a pointer to the Auth token field.

## Upgrade notes

- No schema change. `git pull && make image`, recreate the container.
- After upgrading, use "Send test delivery" to sort out the webhook token; the
  stored failed deliveries can then be replayed with "Retry webhook".
