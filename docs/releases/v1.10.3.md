# PnP Bridge 1.10.3

Better VLAN matching for Day-N.

## Fixed

- **An exact VLAN name now wins over a partial one.** A site with a VLAN named
  `access` (299) *and* another named `Time_Access` (1570) was treated as
  ambiguous, so `ACCESS_VLAN` was left for manual entry. The VLAN whose name is
  exactly the keyword now wins outright; names that merely contain the word are
  only considered when no VLAN carries the bare name. The same applies to
  `critical`.

## New

- **`NATIVE_VLAN_ID` is filled with the access VLAN.** The uplink trunk carries
  the access VLAN untagged, so `NATIVE_VLAN` / `NATIVE_VLAN_ID` now resolve to
  the same VLAN as `ACCESS_VLAN` (299 in the example above) instead of being a
  manual field. If the access VLAN itself is only a suggestion, the native VLAN
  is prefilled as an editable field too.

## Upgrade notes

- No schema change. `git pull && make image`, recreate the container.
- Re-run "Resolve variables" on any job sitting on step 4.
