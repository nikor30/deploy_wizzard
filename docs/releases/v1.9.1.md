# PnP Bridge 1.9.1

Private-VLAN configuration is now optional in Day-N.

## Fixed

- **Private-VLAN variables no longer block a Day-N deploy.** `PVLAN`,
  `PRIMARYVLAN` and `SECONDARYVLAN` were treated like every other manual
  variable, so the Deploy button stayed disabled ("Fill in all manual variables
  first") until you typed something into them — even on the majority of switches
  that do not use private VLANs at all. They are now marked **optional**: shown
  as a normal (non-highlighted) field labelled `(optional)`, and left blank they
  simply do not appear in the deploy payload, so the template's own default
  applies. Fill them in and they are sent exactly as before.

  All other manual variables stay required.

## Upgrade notes

- No schema change. `git pull && make image`, recreate the container.
- Jobs already sitting on step 4 need "Resolve variables" once more to pick up
  the optional flag.
