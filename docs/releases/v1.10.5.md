# PnP Bridge 1.10.5

Actionable guidance when Catalyst Center rejects a push over an interactive prompt.

## New

- **Interactive-prompt failures now explain themselves.** When a template
  contains a command that makes IOS ask a question, Catalyst Center rejects the
  entire push as `Invalid CLI` — it only auto-answers the prompts it knows
  (`[y/n]`, `[confirm]`, `ACCEPT?`). A bare `Do you wish to continue? [yes]:`
  is not one of them.

  The Day-N error now appends what to do about it: wrap the command in the
  Catalyst Center template with the interactive syntax,

  ```
  #INTERACTIVE
  authentication display new-style<IQ>Do you wish to continue? [yes]:<R>yes
  #ENDS_INTERACTIVE
  ```

  This is the common case for `class-map type control subscriber` (C3PL)
  commands pushed to a switch still in legacy authentication mode: the first
  C3PL command triggers the irreversible legacy→new-style conversion, and the
  conversion prompts.
