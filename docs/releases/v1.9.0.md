# PnP Bridge 1.9.0

Day-N variables now prefill from NetBox out of the box.

## Fixed

- **Day-N variables fill from NetBox without manual mapping.** Day-N resolved
  variables *only* through the mapping table you configured by hand — unlike
  Day-0, which has built-in aliases — so on a real template almost every field
  came up as a required manual entry. The same built-in approach now covers
  Day-N, using the field choices proven in the `netbox_cc_dayn` project:

  | Variable | NetBox source |
  |---|---|
  | `SITE_FULL_NAME` | site name |
  | `BUILDING_ROOM` / `BASIC LOCATION INFORMATION` | location name |
  | `RACK_ID` | rack name |
  | `RACK_POSITION` | rack unit |
  | `DEVICE_ROLE` | device role |
  | `ASSET_ID` | asset tag |
  | `SUPPORT_CONTACT` | site contact (role "Local IT") → device contact → tenant |
  | `UPLINK_SWITCH` | far-end device of the cabled uplink |
  | `UPLINK_PORTS` | local names of the cabled interfaces |
  | `ARRVLANS` | all VLANs of the device's site |

  Also covered: hostname, serial, platform, device type and tenant. **An
  explicit mapping in Settings → Day-N Variables always wins**, so you can still
  override any of these.

  Variables with no NetBox source — `PRIMARYVLAN`, `SECONDARYVLAN`,
  `NATIVE_VLAN_ID`, `PO_ID`, `PVLAN` and similar design choices — deliberately
  stay open for manual entry rather than being guessed.

- **CCC's internal and garbled variables are hidden in Day-N too.** The
  `__device` / `__interface` bindings (which Catalyst Center fills itself) and
  the garbled password-derived names were shown as required fields, blocking the
  Deploy button on values nobody could supply. Both are now filtered out of
  Day-N, as they already were in Day-0.

## Upgrade notes

- No schema change. `git pull && make image`, recreate the container.
- Existing Day-N mappings are untouched and continue to take precedence; you can
  delete any that merely duplicate a built-in alias.
